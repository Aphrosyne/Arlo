## 1. 文档定位

这是 Arlo 第二次产品方向重构的活动路线图。

本路线图与以下文档的关系如下：

- `AGENTS.md`：编码边界、安全规则、验证要求和文档优先级。
- `docs/spec.md`：当前产品规格；第二次重构确认后的产品决定会逐步提炼到这里。
- `docs/product-redesign-v2.md`：第二次重构讨论记录，保留想法、理由和待讨论问题，不直接授权编码。

## 2. 重构总目标

Arlo 不再只是一个让用户手动移动 Mod 文件的“工作台”，而是一个本地优先的 Skyrim Mod 资产库：

> 用户把 Mod 本体、汉化包和预览图交给 Arlo，Arlo 分析并提出建议，用户确认一次后形成可浏览、可搜索、可继续补充元数据的内容单元；同时帮助用户控制过大的现役库。

重构需要长期遵守以下产品原则：

1. 真实文件系统仍然是文件内容和组织关系的事实来源。
2. 文件系统是内容单元和文件内容的事实来源；标签等少量元数据由内容单元旁的 `arlo.ini` 保存，不使用数据库作为阶段 1 的持久化元数据来源。
3. 自动分析可以提供证据和候选项，但不能在低置信度时替用户做不可逆决定。
4. 文件移动、复制、删除、重命名和释放本地载荷都必须经过明确确认。
5. 标签应逐步补全，不应成为新内容进入资产库的强制表单。
6. 快速整理、资源库、归档和远程存储属于不同阶段，不能一次性混成一个巨大功能。

## 阶段 1：内容单元、扁平资产根目录、标签基线和运行时索引

> 状态：当前阶段
>
> 阶段 1 先验证新的现役资产根目录、内容单元、`arlo.ini` 标签和运行时索引。旧目录迁移不属于本阶段实现，后续如仍有需要，再作为一次性、独立、可停用的临时模块规划。

### 1.1 阶段目标

把新的现役资产根目录收敛为一套可由资源管理器直接理解的内容单元结构：一级普通文件夹表达内容单元，文件夹名表达身份，`arlo.ini` 保存少量标签元数据，扫描结果可以直接重建运行时索引。

阶段 1 不追求智能识别、完整快速整理 UI 或旧目录转换。当前批次先保证结构边界、标签读写、一级扫描、内存索引和失败可见，为后续 UI 和一次性迁移模块留下稳定接口。

### 1.2 阶段 1 的基线决策

以下内容作为本阶段的设计约束：

- 第一版严格只建立一个现役资产根目录；不实现多个管理根目录聚合。
- 根目录下的每个普通顶层文件夹建立运行时 `ContentUnit` 索引；没有标签的内容单元仍然有效，进入“未整理”视图。扫描不依赖数据库记录，也不移动、复制或删除文件。
- 根目录下的松散文件属于“待处理异常”，只提醒和列出，不自动猜测归属，也不在启动时用模态窗口打断用户。
- 内容单元内部直接放置原始包、汉化包和预览图等文件，保留原始文件名，不强制增加 `payload/`、`original/` 或 `previews/` 子目录。
- 当前资产库扫描直接使用已有文件夹名作为内容单元名称和身份；名称提取、重命名冲突和导入命名规则不在本批实现。
- 标签不阻塞内容单元建立。系统状态与内容标签分离，不把“已汉化”“待测试”等状态写入普通标签。
- 初始本地标签以已确认的第一版清单为基线；标签持久化使用稳定小写 ASCII ID，显示名称由标签目录维护。作者和来源暂不进入阶段 1 标签模型。
- 阶段 1 不把旧数据库作为输入，也不建立数据库迁移、兼容层或与 `arlo.ini` 的双向同步。
- 新代码通过 Application 服务访问扫描和标签写入；UI 不直接写 `arlo.ini`。

### 1.2.1 阶段 1 预先冻结的简化边界

以下决定在阶段 1 前冻结，后续实现不得重新引入旧方向：

- 内容单元文件夹名就是唯一名称和身份，不存在别名或显示名称；
- 持久化元数据只保留标签和 `arlo.ini` schema 版本；
- 所有标签属于同一层级，不使用主分类/辅助标签两套业务模型；
- 不持久化备注、作者、来源、归档、云端、操作历史、路径和预览图引用；
- `arlo.ini` 是标签事实来源，数据库不参与阶段 1 的内容单元元数据；
- 一个现役资产根目录，一级文件夹直接作为内容单元；
- 目录树、装配面板、复杂撤销历史和多根目录管理不进入新 UI；
- 快速整理的完整导入分析 UI 放在后续阶段；阶段 1 只固定内容单元和标签接口；
- 启动扫描只做一级、浅层读取；运行时索引可以丢弃并从文件系统和 `arlo.ini` 重建；
- 旧目录迁移不属于阶段 1 常驻核心功能，不能以迁移代码反向引入数据库、长期映射或通用同步系统。

详细边界见 `docs/simplification-plan.md`。阶段 1 可以暂时保留旧代码，但新实现不得继续依赖这些被冻结的概念。

### 1.3 阶段输入与输出

**输入：**

- 用户确认的现役资产根目录、其一级文件夹和内容单元旁的 `arlo.ini`；
- 应用设置和可重建的缩略图缓存；
- 已确认的标签 ID 与显示名称目录。

旧数据库、旧分类目录树、作者/来源字段和历史操作记录不是阶段 1 新资产库的输入。

**输出：**

- 一个现役根目录下的内容单元、松散文件、忽略项和扫描异常结果；
- 可以按规范化路径查找、按标签筛选和按名称/标签搜索的运行时索引；
- 通过 Application 服务读写 `arlo.ini` 的标签接口；
- 可由文件系统和 `arlo.ini` 重建的内容单元结构，不依赖数据库持久化记录。

### 1.9 阶段 1 验收标准

阶段 1 只有在以下条件都满足时才算完成：

- 规格和架构明确描述一个现役扁平根目录、顶层内容单元、松散文件异常和 `arlo.ini` 边界；
- 核心模型不依赖数据库，能够从文件系统和 `arlo.ini` 重建内容单元名称、文件和标签；
- 内容单元保留原始文件名，路径比较支持中文、Unicode、大小写差异和跨盘路径；
- 标签 ID 与显示名称分离，标签不阻塞内容单元建立，系统状态不冒充内容标签；
- `arlo.ini` 能够稳定读写、损坏可见、无标签内容单元仍可正常显示；
- 扫描结果能够报告松散文件、隐藏/系统项、符号链接、失效根目录和损坏元数据；
- 运行时索引支持重建、路径查找、标签筛选和基本搜索，不依赖旧数据库或目录树；
- 中文路径、中文标签、缺失/损坏元数据、重复扫描和部分失败均有自动化测试；
- 本阶段没有混入旧目录迁移、完整快速整理 UI、AI 分类、容量归档、网盘功能或旧文件管理器能力。
