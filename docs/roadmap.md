## 1. 文档定位

这是 Arlo 第二次产品方向重构的活动路线图。

本路线图与以下文档的关系如下：

- `AGENTS.md`：编码边界、安全规则、验证要求和文档优先级。
- `docs/spec.md`：当前产品规格；第二次重构确认后的产品决定会逐步提炼到这里。
- `docs/product-redesign-v2.md`：第二次重构讨论记录，保留想法、理由和待讨论问题，不直接授权编码。
- `docs/architecture.md`、`docs/technical-debt.md`：当前技术结构与遗留问题。
- `archive/`：历史资料，不作为当前路线依据。

当本路线图与代码冲突时，先检查代码、测试和 `CHANGELOG.md`，再修订路线图；不能仅凭复选框假定工作已经完成。

## 2. 重构总目标

Arlo 不再只是一个让用户手动移动 Mod 文件的“工作台”，而是一个本地优先的 Skyrim Mod 资产库：

> 用户把 Mod 本体、汉化包和预览图交给 Arlo，Arlo 分析并提出建议，用户确认一次后形成可浏览、可搜索、可继续补充元数据的内容单元；同时帮助用户控制过大的现役库。

重构需要长期遵守以下产品原则：

1. 真实文件系统仍然是文件内容和组织关系的事实来源。
2. 数据库是元数据增强层，不应成为用户文件的唯一载体。
3. 自动分析可以提供证据和候选项，但不能在低置信度时替用户做不可逆决定。
4. 文件移动、复制、删除、重命名和释放本地载荷都必须经过明确确认。
5. 标签应逐步补全，不应成为新内容进入资产库的强制表单。
6. 快速整理、资源库、归档和远程存储属于不同阶段，不能一次性混成一个巨大功能。

## 3. 阶段总览

后续阶段名称是当前规划方向，不代表已经完成详细设计：

| 阶段 | 方向 | 状态 |
| --- | --- | --- |
| 阶段 0 | 产品身份、文档依据和程序入口统一 | **当前阶段** |
| 阶段 1 | 内容单元、扁平资产根目录、标签基线和旧目录迁移 | 待阶段 0 完成后细化 |
| 阶段 2 | 自动分析与快速整理面板 | 待阶段 1 验证后细化 |
| 阶段 3 | 资源库 UI、卡片浏览、筛选和封面体验 | 待阶段 2 验证后细化 |
| 阶段 4 | 容量分析、归档候选、上传记录和首个存储适配 | 待阶段 3 验证后细化 |
| 阶段 5 | 打包、单一快捷方式、公开测试和反馈迭代 | 核心功能稳定后进行 |

阶段 1 之后的内容只能作为方向索引，具体输入、输出、失败行为和验收标准必须在进入阶段前补齐。

## 阶段 0：项目身份与入口统一

### 0.1 阶段目标

清理第一次编码和第一次重构留下的项目身份、文档引用和入口残留，使后续代码工作都围绕同一个产品名称和同一套活动文档进行。

阶段 0 的核心结果不是增加用户功能，而是建立一个不会继续制造旧名称和旧方向遗留的开发基线。

### 0.2 已确认决策

- 产品正式名称为 **Arlo**。
- 产品只保留一个逻辑启动入口；快速整理和资源库不能各自形成独立快捷方式。
- 改名和入口统一属于阶段 0，不在后续功能开发中零散处理。
- 旧的交接文档、第一次路线图和第一次 UX 重构资料已经归入 `archive/`。
- `docs/product-redesign-v2.md` 当前继续作为讨论记录；确认后的内容再提炼到 `docs/spec.md` 和本路线图。
- 打包和快捷方式的最终制作仍然晚于核心功能，但源代码层的入口语义应先统一。
- 旧应用数据目录、数据库和设置文件不能因为改名直接失效，兼容或迁移方案必须先明确。

### 0.6 阶段验收标准

阶段 0 只有在以下条件都满足时才算完成：

- Arlo 是唯一的用户可见产品名；旧名称只出现在兼容逻辑、迁移记录或历史资料中。
- 开发环境和未来打包环境都只有一个逻辑应用入口。
- 现有数据库、设置、缩略图和用户文件不会因改名被自动移动、删除、覆盖或重建。
- README、活动文档和入口帮助不再指向已经归档的权威文档。
- 旧代码遗留已被清点，未决定删除的功能没有被伪装成已经完成的新设计。
- 中文路径、UTF-8、已有数据读取和数据库迁移测试通过。
- `ARLO_DATA_DIR` 的优先级与默认目录行为有回归测试；`start_arlo.bat` 和 `arlo` 命令能够启动同一应用入口。
- `pyproject.toml`、README/活动文档和 `CHANGELOG.md` 中的当前版本信息一致；版本变更没有只改其中一处。
- 阶段 0 的活动文档、代码和验证结果已提交，工作树中的未完成项已明确列出，不把未验证内容标为完成。
- 阶段 0 没有偷偷混入快速整理、标签重构、云端存储或大规模 UI 功能。
- `CHANGELOG.md` 和本路线图能够准确描述实际完成内容与剩余问题。
