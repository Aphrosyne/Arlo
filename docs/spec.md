# Arlo — 产品规格说明

> 本文档为方向 C 确认后的重写版。旧版已归档至 `archive/`。
>
> 设计决策来源：`docs/product-review.md`（产品复盘）、`docs/design-workbook.md`（设计工作手册）

---

## 1. 项目定位

Arlo 是一个面向 Windows 的、本地优先（local-first）的本地数字资产管理工具（DAM, Digital Asset Management）。第一阶段专门优化 Skyrim Mod 的整理与浏览工作流，但核心模型（内容单元文件夹 + 旁侧标签文件）可扩展到其他资产类型。

它不替代 Mod Organizer 2、Everything 或 Windows 资源管理器。它解决的核心问题是：用户有大量零散放置的本地数字资产（Mod 文件、教程、素材、截图），需要通过预览、中文信息、标签和可交互的目录树，快速完成识别、标记、分类与归档。

项目计划开源，第一版不包含云同步、账号系统或用户数据上传。

## 2. 核心原则

### 2.1 模型原则

- **真实文件系统是唯一的事实来源（Single Source of Truth）**：文件始终是普通文件，能够脱离本程序继续被资源管理器、MO2 和其他工具使用。
- **`arlo.ini` 是内容单元的元数据文件**：Arlo 不使用数据库保存阶段 1 的持久化元数据；标签随内容单元文件夹保存，名称、路径和预览图由文件系统或规则推导。
- **内容单元由真实文件夹表达**：现役根目录下的一个顶层文件夹就是一个内容单元，不建立数据库记录作为身份，也不是虚拟条目。
- **标签替代物理分类目录**：现役资产根目录直接放置内容单元文件夹，细分类由统一标签和筛选承担。

### 2.2 安全原则

- 所有文件操作直接作用于真实文件系统（不再是预演→确认→执行的模式），但保留必要的安全机制。
- 文件移动前弹出确认提示；重名冲突时弹窗让用户选择（覆盖/跳过/重命名）。
- 禁止将文件夹移动到自身或子目录。
- 跨盘移动需明确提示用户。
- 删除操作统一移至 Windows 回收站。
- 阶段 1 不建立持久化操作历史表；文件操作通过确认、校验和失败报告保证可解释性。

### 2.3 中文优先

- 真实路径和文件名可为中文（MO2 对中文路径支持良好，无需回避）。
- **内容单元文件夹名就是唯一名称，也是内容单元的身份**：不存在内部名称和显示名称，不支持别名、昵称或自定义显示名。显示、搜索和内容单元身份一律使用真实文件夹名；文件夹改名即内容单元改名。
- 所有 UI 优先使用中文显示。
- 搜索完整支持中文和 UTF-8。

### 2.4 技术原则

- Python 3.12+ / PySide6 / Pillow；阶段 1 不依赖 SQLite 或 FTS5
- local-first：所有数据保存在本机，不上传用户文件、路径、图片或元数据
- 不依赖统一命名规则：不假设 Nexus Mods、汉化包、社区分享文件或预览图存在可靠命名规律
- 不读写压缩包内部内容
- 不修改用户原图（缩略图缓存写入应用数据目录）

## 3. 第一版目标

第一版的目标是让用户能够完成一次完整的"暂存区整理 → 元数据标记 → 分类放入"工作流，并能够舒适地浏览和检索已有内容。

### 范围

1. 扫描用户指定的受管理根目录，通过增量扫描维护目录缓存。
2. 自动识别所有压缩包文件为内容单元候选，文件夹由用户手动标记。
3. 以基础分类目录树（一级或二级）展示资产库结构。
4. 提供单面板统一 UI：目录树 + 文件列表（列表/卡片视图 + 标签筛选 + 大图预览）+ 右栏（元数据 + 可钉住装配面板）。
5. 支持在任意目录内创建 Mod 组（自动提取名称 → 建文件夹 → 移入文件）。
6. 支持将文件添加到钉住文件夹（右键菜单或拖拽），以及文件夹/文件移动到目标分类目录。
7. 为内容单元设置标签；名称始终使用真实文件夹名，预览图按规则推导，备注和别名不属于阶段 1 元数据。
8. 预置 Skyrim 标签库，支持自定义标签和统一标签筛选。
9. 全局搜索（真实文件夹名 + 文件名 + 标签）。
10. 基础文件操作：重命名（同步更新路径）、删除（移至回收站）、复制路径。
11. 基础文件操作具备明确确认和失败报告；阶段 1 不持久化操作历史。
12. 导出待整理内容单元列表为 JSON，提供给外部网页 AI 分类建议。
13. 导入 AI 建议的 JSON，在本地审阅并确认后应用。
14. 缩略图缓存与预览图展示。

### 非目标

第一版不包含以下功能：

- 云同步、账号、多人协作或远程数据库。
- 替代 MO2 的安装、排序、启用、冲突管理或游戏启动功能。
- 替代 Everything 的全盘文件搜索。
- 不经用户确认的自动文件移动、删除、覆盖或重命名。
- 从 Nexus Mods 自动批量抓取预览图。
- 解析压缩包内部图片或内容。
- 文件哈希去重、完整文件监听、MO2 深度联动。
- 本地 AI 推理或 AI 直接控制文件系统。
- 非 Mod 类型的内容单元元数据管理（教程、截图等暂通过文件系统直接浏览，不入库）。

## 3.1 阶段 1 资产结构基线

阶段 1 先固定资产库的结构边界，再实现迁移工具。第一版只允许一个现役资产根目录；应用配置和扫描范围围绕这个根目录工作，不把多个管理根目录聚合成一个逻辑资产库。切换现役根目录必须是用户明确执行的配置操作，不能由扫描过程自动改变。

现役根目录下的每个普通顶层文件夹代表一个内容单元。扫描发现后，Arlo 可以为它建立 `ContentUnit` 元数据记录；这个登记过程只写数据库，不移动、复制、重命名或删除文件。没有标签的内容单元仍然有效，进入“未整理”状态，标签不能阻塞内容单元建立。

现役根目录下的松散文件属于“待处理异常”。Arlo 只列出其路径、文件类型和基本信息，等待用户后续处理，不在启动时猜测归属，也不自动创建内容单元文件夹。

内容单元文件夹内部暂时直接放置原始包、汉化包和预览图等文件，保留原始文件名，不强制增加 `payload/`、`original/` 或 `previews/` 子目录。内容单元文件夹重名必须进入冲突处理流程，不能静默覆盖或自动合并。

### 3.2 发现、迁移与文件操作边界

目录发现和旧目录迁移是两个独立步骤：

- 发现阶段只读扫描并生成候选、松散文件和异常清单，不改变用户文件或 `arlo.ini` 之外的文件系统状态。
- 迁移阶段先生成可审阅预览，再由用户明确选择复制或移动模式。首版默认复制并保留源文件；将源文件移入回收站必须是单独确认的动作。
- 任何冲突、权限错误、路径过长、空间不足或 `arlo.ini` 写入失败都必须出现在报告中，不能把部分完成标记为成功。
- 迁移完成后校验文件数量、大小和目标路径；源文件在校验失败时应保持可用。

上述规则是阶段 1 的结构约束；自动分析、快速整理、批量标签建议和真实大库迁移不在本批规格基线中。

## 4. 核心数据模型

### 4.1 ContentUnit（内容单元）

内容单元由现役资产根目录下的一个普通顶层文件夹表达。文件夹名是唯一名称，也是内容单元的身份。

~~~text
folder_name: str          # 真实文件夹名；唯一名称和身份
folder_path: Path         # 运行时由现役根目录和 folder_name 推导
tags: list[str]           # 从旁侧 arlo.ini 读取
cover: Path | None        # 按预览图选择规则运行时推导，不作为核心元数据
~~~

明确规则：

- 不存在内部名称、显示名称、别名、昵称或自定义显示名；
- 文件夹改名即内容单元改名；
- 不持久化绝对路径；
- 不持久化重复的名称字段；
- 内容单元可以没有 arlo.ini，此时视为无标签/未整理。

### 4.2 arlo.ini

每个内容单元可以在文件夹内放置一个 Arlo 专属的 arlo.ini：

~~~ini
[Arlo]
schema=1
tags=clothing,ube
~~~

arlo.ini 只保存 Arlo 无法从文件系统直接推导、且需要跨启动保留的标签信息。无标签内容单元可以不创建该文件。

实现要求：

- 标签使用稳定内部 ID，不使用显示文本参与业务判断；
- 写入采用临时文件替换等原子方式；
- 缺失 arlo.ini 等同于无标签；
- 损坏或格式不正确时显示异常，不静默覆盖；
- 使用 arlo.ini 而不是通用 meta.ini，避免与 Mod 内容自带的 meta.ini 混淆。

### 4.3 Tag（统一标签）

主分类和辅助标签合并为一个标签集合。每个标签具有稳定 ID 和显示名称，不再存在 TagCategory 或 ContentUnitTag 数据库实体。

### 4.4 运行时索引

Arlo 启动或扫描后，在内存中建立内容单元和标签索引，用于搜索、筛选和卡片显示。该索引不是持久化事实来源，可以随时从文件系统和 arlo.ini 重建。

### 4.5 运行时缓存

- 预览图缩略图是应用缓存，不属于内容单元核心元数据；
- 现役资产根目录是应用设置，不属于单个内容单元元数据；
- 如未来需要性能缓存，缓存不得取代文件系统和 arlo.ini 作为事实来源。
## 5. 用户工作流

### 5.1 浏览模式（默认）

浏览模式的用途：浏览目录内容、查看和筛选内容单元、执行基础文件操作。

```
用户启动应用
    ↓
启动时自动扫描（增量扫描基于目录 mtime，跳过未变更目录）
    ↓
左侧目录树显示基础分类结构
    ↓
选中一个目录 → 中间显示该目录下的所有文件和文件夹
    ├─ 已被识别为内容单元的 → 显示 [内容单元] 标记和封面
    ├─ 未被识别为内容单元的 → 正常显示，无标记
    └─ 所有条目均可右键操作（复制路径、重命名、标记为内容单元等）
    ↓
在顶部标签栏筛选：
  ├─ 仅对已被标记为内容单元的项目生效
  ├─ 点击标签分类 → 展开标签 → 多选 → 列表实时筛选
  └─ 支持排序切换（名称/日期/类型/大小/状态 + 正序/倒序）
    ↓
单击内容单元 → 右栏立即显示元数据（详情面板交互方式）
双击文件夹（无论是否内容单元）→ 进入该目录（等价于目录树切换）
双击文件类型内容单元（压缩包）→ 显示元数据编辑面板
双击非内容单元文件 → 不响应
```

**关键设计**：
- 内容单元不是"可见性门槛"。文件系统里有什么，中间列表就显示什么。
  内容单元只是在文件基础上增加了**标记**和**元数据**，不影响文件本身是否可见。
- 元数据作为"详情面板"，单击查看更符合资源管理器/IDE/DAM 软件的交互习惯。
  文件夹的元数据通过单击查看；双击文件夹优先进入目录（而非显示元数据）。
- 扫描/创建 Mod 组等刷新操作后，目录树尽量保持原有展开状态与选中节点，
  避免用户每次都需要重新一级级展开。

### 5.2 整理流程（统一面板，原"整理模式"已移除）

整理用途：从零散文件创建 Mod 组、分类放入、重命名、删除。
UX 重构 Phase 1 已移除"浏览/整理"双模式切换与暂存区概念，所有操作在统一面板中完成。

```
【创建 Mod 组】（中栏右键，单/多选文件）
  ├─ 自动从文件名提取主要名称（剔除版本号、无用后缀等）
  ├─ 下拉框供选择：纯 Mod 名 / 完整原名
  ├─ 确认后以所选名字在当前目录创建真实文件夹，选中文件移入
  └─ 文件夹标记为内容单元
    ↓
【装配】
  ├─ 单击文件夹（内容单元或普通文件夹）→ 右栏下方装配面板透视其内部文件
  ├─ 📌 钉住装配面板 → 中栏右键"添加到钉住文件夹"或直接拖拽到装配面板
  ├─ 预览图可通过装配面板右键手动重命名为文件夹名
  └─ 装配完成
    ↓
【放入分类目录】
  ├─ 装配面板右键空白处 → "移动到……"（移动整个文件夹）
  ├─ 中栏/目录树右键 → "移动到……"（任意文件/文件夹移动）
  └─ 或复制/剪切 + 粘贴（跨目录）
    ↓
【直接操作】
  ├─ 中栏内拖拽文件到同目录文件夹 = 移入该文件夹
  ├─ 右键重命名（真实文件夹改名 + 同步更新 ContentUnit.path）
  ├─ 右键删除（移至回收站）
  └─ 右键复制路径
```

### 5.3 暂存区（已移除）

> 暂存区标记/列表功能已于 UX 重构 Phase 1 Task 1（v0.42.0 起）整体移除，
> 相关表（staging_area，schema v12 删除）与代码不再存在。
> 原"设置暂存区"流程（标记任意目录为暂存区）已废弃，不再支持。

### 5.4 扫描

```text
启动时自动增量扫描：
  - 遍历每个已知目录，对比当前 mtime 与上次扫描记录
  - mtime 未变 → 跳过
  - mtime 变化 → 重新扫描该目录及子目录

内容单元识别规则：

- 现役资产根目录下的普通顶层文件夹自动识别为内容单元；
- 没有 `arlo.ini` 或没有标签的内容单元进入“未整理”状态；
- 根目录松散文件进入“待处理异常”，不自动创建内容单元；
- 不使用数据库记录作为内容单元存在与否的依据；
- 不做实时文件系统监听（避免 CPU 负载影响游戏）。

用户可随时手动触发全量重新扫描。
不做实时文件系统监听（避免 CPU 负载影响游戏）。
```

### 5.5 AI JSON 交换（第一版后期）

```text
[优先级靠后，先完成手动整理体验]

导出：
  - 选中未整理的内容单元 → 导出 JSON（含路径、文件名、大小、当前标签）
  - 可选导出已有分类目录结构

导入：
  - 导入 AI 返回的建议 JSON
  - 审阅差异（建议中文名、建议分类、建议标签）
  - 逐项或批量勾选确认
  - AI 只生成建议，不直接操作文件系统
```

## 6. 文件操作安全规则

### 6.1 移动

| 规则 | 策略 |
|------|------|
| 节点间移动 | 弹出确认提示，防止误操作 |
| 重名冲突 | 阶段 5 Task 3b 已实现通用冲突解决（ConflictResolutionDialog）：弹窗让用户选择 覆盖 / 跳过 / 重命名；选择覆盖时以 overwrite=True 先删除目标再执行（AGENTS 规则 2：不经确认不覆盖） |
| 跨盘移动 | 提示"跨盘移动暂不支持"并拒绝（当前阶段跨盘场景较少，且 Windows 跨盘 move 会退化为 copy+delete，风险较高） |
| 文件夹移到自身或子目录 | 阻止并提示（此操作不合理） |

### 6.2 删除

- 统一移至 Windows 回收站。
- 操作历史记录删除操作，实际撤销能力由回收站提供。

### 6.3 重命名

- 在应用内重命名：同时修改真实文件夹名和 ContentUnit.path。
- 在应用外重命名：原"路径丢失检测与重新关联"功能（Stage 5 Task 3c）已延期开发，
  代码归档于 `stage5-task3c-suspended` 分支，主线不包含；恢复前以重新扫描为准。

### 6.4 撤销

- 所有操作记录到 operation_history 表。
- 撤销时检查文件当前状态是否安全，不安全时阻止。

## 7. UI 结构

### 7.1 整体布局（统一面板）

UX 重构 Phase 1 起为单面板统一工作区，无"浏览/整理"模式切换：

```text
┌─── 顶部工具栏：搜索框 + 标签管理 + 操作历史 ───────────────┐
├──────────┬──────────────────────────┬─────────────────────┤
│          │                          │                     │
│  目录树   │    中栏：文件列表          │  右栏（3:2 分割）   │
│  （左侧） │    ├─ 标签筛选栏         │  ┌ 元数据编辑面板 ┐  │
│          │    ├─ 列表/卡片视图切换   │  │ 重命名/标签/来源/ │  │
│  AssetLib │    ├─ 排序/缩放/前进后退 │  │ 标签与扫描信息  │  │
│  ├─ Mods  │    └─ 刷新（F5）        │  ├────────────────┤  │
│  │├Armor  │                          │  │ 装配面板       │  │
│  │├Magic  │                          │  │（📌 钉住）     │  │
│          │                          │  └────────────────┘  │
└──────────┴──────────────────────────┴─────────────────────┘
└─── 状态栏（QStatusBar：扫描状态 / 提示）───────────────────┘
```

要点：
- 单击内容单元 → 右栏元数据面板；单击文件夹 → 装配面板透视其内部文件（可 📌 钉住）
- 所有文件操作（新建文件夹 / 重命名 / 删除 / 复制剪切粘贴 / 移动到……）在统一面板中可用
- 顶部无模式切换按钮（Phase 1 Task 1 移除）

### 7.2 内容浏览

- 点击目录树节点 → 中间显示该目录下的**所有文件和文件夹**
- 已被识别为内容单元的项目 → 显示内容单元标记（图标、封面）
- 未被识别为内容单元的项目 → 正常显示为普通文件/文件夹
- 右键菜单对所有项目可用（复制路径、重命名、删除）
- 未标记的文件/文件夹可右键 → "标记为内容单元"
- 已标记的内容单元可右键 → "取消标记"
- 顶部标签筛选栏：先选标签分类 → 展开标签 → 多选（仅过滤已标记的内容单元）
- 排序：名称 / 修改日期 / 类型 / 大小，正序/倒序切换
- 视图切换：详细列表 / 大图卡片（卡片尺寸 96~256 预选档），缩放不影响列表视图
- 前进/后退目录导航（类似资源管理器，同会话内）
- **内容单元不是可见性门槛**。所有文件系统内容都能在应用中看到和操作。
- **交互方式（2026-07-16 调整）**：
  - 单击选中内容单元 → 右栏立即显示元数据（详情面板交互方式）
  - 双击文件夹（无论是否内容单元）→ 进入该目录（等价于目录树切换）
  - 双击文件类型内容单元（压缩包）→ 显示元数据编辑面板
  - 双击非内容单元文件 → 不响应
- **展开状态保持**：扫描/创建 Mod 组等刷新操作后，目录树尽量保持原有展开状态与选中节点。

### 7.4 装配面板（文件夹透视器，右栏下方）

- 常驻右栏下方（元数据面板之下，3:2 分割），始终可见，未绑定时显示空状态占位
- 语义为"文件夹透视器"：单击文件夹（内容单元或普通文件夹）→ 显示其内部文件列表
- 📌 钉住：钉住后中栏操作不改变装配面板绑定；取消钉住后跟随中栏选中
- 文件添加：中栏右键「添加到钉住文件夹」（仅钉住时可见）或直接拖拽文件到装配面板
- 右键菜单继承中栏文件操作：重命名 / 复制 / 剪切 / 粘贴 / 移动到…… / 删除 / 复制路径
- **不自动重命名图片**：自动整理阶段不修改任何文件名，避免破坏用户已有命名
- **手动重命名预览图**：右键图片 → "重命名为与文件夹同名"，
  执行后图片重命名为 `{文件夹名}.{扩展名}`；多张图片时采用
  `{文件夹名}_2.{扩展名}`、`{文件夹名}_3.{扩展名}`……后缀；
  命名冲突走现有 `ConflictError` 流程（弹窗提示冲突，不覆盖，AGENTS 规则 2）
- 右键空白处 → "移动到……"：移动整个透视文件夹，成功后自动取消钉住
- 「加入装配」「移除文件」入口均已移除（由剪切/移动到/添加到钉住文件夹替代）

## 8. 搜索

第一阶段搜索范围：

- 内容单元文件夹名；
- 内容单元内部文件名；
- arlo.ini 中的标签。

搜索启动后基于当前文件系统扫描结果和内存标签索引，不依赖数据库全文索引。文件夹名变化后，以重新扫描到的真实名称为准。
## 9. 预览图

- 内容单元可从其目录内的图片中按固定规则选择预览图。
- 预览图引用不是阶段 1 的核心持久化字段。
- 应用生成的缩略图保存到应用缓存目录，不修改原始图片。
- 缩略图缓存可以根据内容单元相对路径、图片文件修改时间或内容校验信息重建。
- 无图片时显示无封面状态。
- 以后如果支持用户在多张图片中固定选择某一张，再单独增加封面选择字段。
## 10. 标签系统

### 10.1 统一标签模型

主分类和辅助标签合并为同一个标签集合。所有标签平等参与筛选，不要求每个内容单元拥有主分类。

标签使用稳定内部 ID 和可本地化的显示名称。系统状态（未整理、收藏、待上传、仅云端等）不写入普通内容标签。

### 10.2 标签文件

标签保存在内容单元旁的 arlo.ini：

~~~ini
[Arlo]
schema=1
tags=clothing,ube
~~~

标签文件随内容单元移动和复制。没有标签时可以没有 arlo.ini。

### 10.3 初始标签

- 初始标签参考 Nexus Mods 基础大类并按 Arlo 实际使用删减；
- 根据需要补充 UBE 等本地标签；
- 作者可以作为普通标签使用；
- 不建立主分类/辅助标签两套持久化结构；
- 本地化只改变显示名称，不改变标签 ID。

### 10.4 UI 交互

- 筛选：选择一个或多个标签，实时筛选内容单元；
- 打标签：单个或批量添加、移除标签；
- 未读取到 arlo.ini 的内容单元进入“未整理”视图；
- 标签读取或写入失败时显示明确错误，不静默丢弃已有标签。
## 11. 持久化与运行时索引

### 11.1 持久化事实来源

阶段 1 不使用数据库保存内容单元元数据。事实来源为：

- 内容单元文件夹及其真实文件；
- 内容单元旁的 arlo.ini 标签文件；
- 应用设置中的现役资产根目录。

### 11.2 运行时索引

Arlo 启动或扫描时读取现役根目录下的内容单元文件夹和 arlo.ini，建立内存索引，用于搜索、筛选和显示。

运行时索引可以在未来增加缓存实现，但缓存不是用户数据，也不能替代文件系统和 arlo.ini。

### 11.3 旧数据库

旧数据库不属于阶段 1 的必要输入。由于现有数据量有限，未来如确实需要保留旧标签，再编写一次性、逻辑简单的转换脚本，将标签写入对应内容单元的 arlo.ini。

不为旧数据库建立复杂兼容层、长期同步机制或通用迁移框架。
